# 数据流与代码结构

浏览器负责采音与显示，本地 Node.js 服务负责保存音频、调度识别和翻译、输出 SSE 和会议包。API Key 只在后端使用。

```text
麦克风 → AudioWorklet → 16 kHz PCM16 → 本地音频上传与 WAV 保存
                                            ↓
                                本地人声检测 → 分段与累计 WAV 识别
                                            ↓
                                    句子缓冲与短字幕切分
                                            ↓
                                       三语翻译
                                            ↓
                                 同 ID 修订 → SSE → 浏览器
                                            ↓
                                    定稿 SRT / 会议记录
```

`npm start` 从 `src/server.js` 启动。默认数据目录和 `.env`、`public/` 均按项目根目录定位，不随源码目录层级变化。

每场会议的名称与可选描述保存在会话记录中，组成 ASR 请求的 `prompt` 与翻译的 `background`。服务配置只保存连接和模型。会议背景不跨场共享，描述不进入只读观看数据，读取历史不会重跑模型。

## 音频和模型调度

浏览器重采样先经过 Blackman 窗 sinc FIR 低通滤波，再按相位系数转换为 16 kHz。降采样截止频率为 7.2 kHz；滤波前视约 3 ms，时间位置使用整数计算以避免累计漂移。暂停和结束时排空滤波器及尾包，上传层将最后不足 100 ms 的帧补静音，原始采样全部保留。

浏览器每 200 ms 上传 PCM，后端按 100 ms 帧分析。分段保留约 300 ms 前置音频，约 700 ms 静音后结束，连续讲话最长约 12 秒，并在尾部较安静的位置寻找切点。

Silero VAD 在本地 CPU 上区分人声与噪声。随项目分发 ONNX 模型，通过 `onnxruntime-node` 运行；每 512 个采样（32 ms）推理，保留循环状态、64 个上下文采样和不足一窗的余量。每个 100 ms 帧采用窗口最大人声概率，起声阈值 0.5、续声阈值 0.35。音量只用于寻找长段的较安静切点，识别入口不再单凭音量触发。

完整音频先落盘，包含静音和噪声；本地检测在独立顺序队列中运行，上传确认不等待推理。未检测到人声的音频保存在 WAV 中，不发送给 ASR。检测失败保留尚未处理的帧及其偏移，暂停后可重试；积压 12 秒时触发采音背压。模型与许可见 `assets/silero-vad/`。

一段音频累计至少 1 秒后尝试临时识别，后续更新间隔至少 1 秒。每次发送当前段的累计 WAV，因此这是应用层增量识别，不依赖服务商原生流式接口。第一次识别结果即可显示原文；连续两次识别的一致前缀进入翻译，尚未确认的尾部只作原文显示。原文修订使用同一字幕 ID 和更高显示版本；服务忙时可跳过中间轮次，最终识别优先，不丢弃最终音频。

翻译使用当前未定稿句子的完整文本和受限上下文，一次返回中、英、粤字幕。临时请求只保留最新版本；已定稿句子不被迟到的旧结果覆盖。音频段结束不等于句子完成，句子可跨停顿，长句拆为短字幕后按同一 ID 与时间轴修订。

英文小写识别结果按句末标点补齐自然句界，适度放宽完整英文句子的短字幕宽度。金额中的空格分组、货币符号和小数位作为同一单位保留，例如 `$12 500.50` 不会被切到两条。原文字符与偏移不改写。

翻译默认使用模型 SSE 流式响应，`eventsource-parser` 处理网络分帧，`@streamparser/json` 在根 `cues` 数组内完整语言字符串闭合后发布字段，不显示未闭合的字符串。提前显示需已验证编号和原文回显；不提供回显的兼容响应等待完整条目。连续条目的已返回语言可独立显示，主持端所选语言优先请求输出，其他语言继续生成。完整三语、整份 JSON 与模型结束信号通过校验后才定稿。显式金额移入其他条目或带不同金额的条目返回同一组三语译文，会触发一次格式重试。

流式临时条目与已校验译文分开保存。失败、取消或过期结果不能晋升为定稿；撤回临时译文时，显示版本也递增，保留识别原文。原文改变后只沿用文本及偏移完全匹配的译文，避免把旧译文配到新原文。识别原文版本与字幕显示版本分别维护，最终字幕时间使用对应翻译源的快照。服务重启时撤去未完成的流式临时译文，保留识别记录，不重跑模型。

当前原文继续增长时，已匹配的译文跨度保留为同一行，未确认尾部接在后面。这样不会因为重新切分整条识别结果而隐藏已返回的译文；后续更高版本仍可在原位置替换这些临时行。

积压达到阈值时暂停采音，待排空后恢复；手动暂停、设备或配置故障阻止自动恢复。暂停和结束均需先停止采音、上传余量、排空识别翻译，再完成相应状态。前端结束需确认。

同场会议只允许一个页面持有采音预留。客户端在请求麦克风前预留，上传时续期，排空后释放；无请求 15 秒后允许其他页面接管。新页面开始时使用服务器保存的结束时间，待上传队列的重试不修改音频时间。预留保存在进程内，服务重启后重新申请，避免多个标签页从旧时间轴同时上传。

## 持久化与恢复

音频和幂等编号写入成功后才确认上传。录音包含采集期间的静音，按小时分卷为 WAV。JSON 会话记录保存识别、修订、字幕与状态；SRT 只写连续的定稿前缀，采用临时文件与原子替换。SRT 条目时间按音频和文本位置估算。

读取历史不重跑模型。服务重启修复已落盘的未完成音频尾部，异常中断会议保留已保存内容；尚未上传的浏览器内存音频无法恢复。删除先写只含会议 ID 和时间的标记，再移除本场文件，重启可继续完成中断的删除。

## 静态资源

音频采集使用项目内的 AudioWorklet 和 PCM 编码器，暂停或结束时先释放麦克风，再取出编码器尾部音频、完成上传。字幕由 `public/transcript.js` 按固定 ID 渲染和滚动。

字体从 Google Fonts 官方仓库直接引入，保留字体作者的 OFL 许可，浏览器从本机加载。具体文件见 [第三方许可](../NOTICE.md)。
